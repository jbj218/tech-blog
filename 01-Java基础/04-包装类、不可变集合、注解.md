# 包装类 + 不可变集合 + 注解：Java 的"细节三件套"

> 这篇博客对应我学过的《TyporaFile/包装类.md》和不可变集合相关知识。

## 一句话定位

**包装类解决"基本类型不是对象"的矛盾；不可变集合解决"集合内容被改"的隐患；注解解决"代码要写很多遍配置"的问题。** 三者都是 Java 基础里的"小工具"，但用得不当会出大问题。

---

## 一、包装类：让万物皆对象

### 1.1 为什么需要包装类

Java 有 8 种基本类型（`int`、`double`、`char`、`boolean`...），它们不是对象——但 Java 是面向对象的语言，**泛型、集合、Object 引用**这些机制只接受对象。

```java
// 报错！基本类型不能做泛型
// ArrayList<int> list = new ArrayList<>();
ArrayList<Integer> list = new ArrayList<>();   // 必须用包装类
```

8 种基本类型都有对应包装类：

| 基本类型 | 包装类 | 缓存范围（自动装箱时） |
| ---- | ---- | ---- |
| `byte` | `Byte` | -128~127 |
| `short` | `Short` | -128~127 |
| `int` | `Integer` | **-128~127** |
| `long` | `Long` | -128~127 |
| `float` | `Float` | 不缓存 |
| `double` | `Double` | 不缓存 |
| `char` | `Character` | 0~127 |
| `boolean` | `Boolean` | true/false |

### 1.2 自动装箱 / 拆箱

```java
// 自动装箱：基本类型 → 包装对象
Integer it3 = 150;
ArrayList<Integer> list = new ArrayList<>();
list.add(138);    // int → Integer 自动装箱

// 自动拆箱：包装对象 → 基本类型
int i1 = it3;
int i2 = list.get(0);
```

### 1.3 缓存机制坑

```java
Integer it1 = Integer.valueOf(100);
Integer it2 = Integer.valueOf(100);
System.out.println(it1 == it2);  // true（缓存了 -128~127）

Integer it3 = 150;
Integer it4 = 150;
System.out.println(it3 == it4);  // false（超出缓存，new 的新对象）
```

> **口诀**：比较包装类一定要 `.equals()`，别用 `==`！

### 1.4 字符串与基本类型互转

```java
int j = 23;

// 基本类型 → 字符串（三种写法）
String s1 = Integer.toString(j);      // 方式 1
String s2 = String.valueOf(j);          // 方式 2（更通用）
String s3 = j + "";                    // 方式 3（最简便）

// 字符串 → 基本类型（两个等价方法）
String str = "98";
int i1 = Integer.parseInt(str);        // 直接返回基本类型
int i2 = Integer.valueOf(str);         // 返回包装类 + 自动拆箱
double d = Double.parseDouble("3.14");
```

> `parseXXX()` vs `valueOf()`：前者直接返回基本类型，后者返回包装类后自动拆箱——结果完全等价。

### 1.5 包装类的实际应用

**最重要的应用**：从外部传来的字符串数值，转成对应基本类型。

```java
// Web 请求参数、表单提交、配置文件读取——全是字符串
String ageStr = request.getParameter("age");
int age = Integer.parseInt(ageStr);   // 用得上包装类的转换能力
```

## 二、不可变集合：不让别人改你的数据

### 2.1 什么是不可变集合

**长度不可变，内容也无法修改的集合**。一旦创建完毕，只能进行查询操作。

```java
List<String> list = List.of("张三", "李四", "王五", "赵六");

// ❌ 全部编译报错
// list.remove("李四");
// list.add("aaa");
// list.set(0, "aaa");
```

### 2.2 为什么需要不可变集合

**防御性拷贝**：把数据交给不可信的库时，不可变形式是安全的。

比如：
1. 斗地主的 54 张牌，不能添加、删除、修改
2. 斗地主的打牌规则（单张、对子、三张……），也是定死的
3. 用代码获取的操作系统硬件信息，不能被修改

### 2.3 三种不可变集合

```java
// List
List<String> list = List.of("张三", "李四", "王五", "赵六");

// Set（元素必须唯一！）
Set<String> set = Set.of("张三", "李四", "王五", "赵六");

// Map（≤ 10 个键值对直接用 of）
Map<String, String> map = Map.of("张三", "南京", "李四", "北京");
// Map（> 10 个键值对）
Map<String, String> bigMap = Map.copyOf(hm);
```

### 2.4 关键细节

| 集合 | of 方法上限 | 替代方案 |
| ---- | ---- | ---- |
| `Map.of()` | **最多 20 个参数（10 个键值对）** | `Map.ofEntries()` / `Map.copyOf()` |
| `Set.of()` | 元素必须唯一 | — |
| `List.of()` | 无上限 | — |

> Map > 10 个键值对的标准做法：
> ```java
> Map<String, String> map = Map.copyOf(hm);
> ```

## 三、注解：给代码贴标签

### 3.1 什么是注解

**注解 = 给类、方法、字段贴的"元数据标签"，本身不影响程序逻辑**，但可以被编译器、框架读取并据此执行特殊操作。

### 3.2 常见注解分类

| 类别 | 示例 | 谁处理 |
| ---- | ---- | ---- |
| JDK 内置 | `@Override`、`@Deprecated`、`@SuppressWarnings` | 编译器 |
| 框架注解 | `@Component`、`@Autowired`、`@Table`、`@TableField` | Spring / MyBatis-Plus 运行时 |
| 自定义注解 | `@MyLog`（自己写的） | 通过反射 / AOP 解析 |
| 元注解 | `@Target`、`@Retention` | 描述注解的注解 |

### 3.3 元注解（注解的注解）

```java
@Target(ElementType.METHOD)             // 注解能贴哪里：方法上
@Retention(RetentionPolicy.RUNTIME)    // 注解保留到哪个阶段：运行时
public @interface MyLog {
    String value() default "";
}
```

| 元注解 | 作用 |
| ---- | ---- |
| `@Target` | 指定注解能贴在哪些元素上（方法、字段、类……） |
| `@Retention` | 指定注解保留阶段（SOURCE / CLASS / **RUNTIME**） |

> 如果自定义注解希望被反射/AOP 读取，必须用 `@Retention(RetentionPolicy.RUNTIME)`。

### 3.4 注解的运行时读取

```java
// 反射 + 注解 = 框架的核心套路
Method m = clazz.getDeclaredMethod("login");
MyLog annotation = m.getAnnotation(MyLog.class);
System.out.println(annotation.value());
```

Spring 的 `@Autowired`、MyBatis-Plus 的 `@TableName`、AOP 切面——全是这套机制。

## 四、总结

| 概念 | 核心价值 | 关键坑 |
| ---- | ---- | ---- |
| **包装类** | 让基本类型参与面向对象 | `==` 比的是引用，包装类要用 `.equals()` |
| **不可变集合** | 防御性保护数据 | `Map.of` 只支持 ≤ 10 个键值对 |
| **注解** | 给代码贴标签，框架据此执行 | 自定义注解若要被反射读取，必须 RUNTIME 级别 |

**一句话**：包装类是基本类型与对象的桥梁；不可变集合是数据的保险箱；注解是框架读你代码的窗口。
