# 泛型：从入门到"泛型擦除"

> 这篇博客对应我学过的《TyporaFile/泛型.md》和《泛型不让做.md》两篇笔记的合并整理。

## 一句话定位

**泛型 = 编译期的类型检查 + 自动强转，JVM 从头到尾都没见过泛型。**

这是理解后面所有细节的总钥匙，记住这句话，下面的东西都顺理成章。

---

## 一、为什么需要泛型

不写泛型时，集合默认什么都收（`Object`），雷就埋下了：

```java
ArrayList list = new ArrayList();
list.add(12);
String s = (String) list.get(0);  // 编译不报错，运行时炸！
// Exception in thread "main" java.lang.ClassCastException:
// class java.lang.Integer cannot be cast to class java.lang.String
```

写上泛型后，编译期就把雷排掉：

```java
ArrayList<String> list = new ArrayList<>();
list.add("msc");
String s = list.get(0);   // 取出来直接就是 String，不用强转
```

**泛型的价值：把运行时才爆的雷，提前到编译期排掉。**

---

## 二、三种泛型形态

| 泛型形态 | 类型变量声明位置 | 类型确定时机 |
| ---- | ---- | ---- |
| 泛型类 | 类名后 `class MyArrayList<E>` | **创建对象时** |
| 泛型接口 | 接口名后 `interface Data<T>` | **实现接口/使用接口时** |
| 泛型方法 | 返回值前 `<T> T getMax(...)` | **调用方法时** |

### 2.1 泛型类

```java
public class MyArrayList<E> {
    private ArrayList list = new ArrayList();

    public boolean add(E e) {
        return list.add(e);
    }
}
```

`new MyArrayList<String>()` 之后，`add` 就只能传字符串——类型约束的来源。

### 2.2 泛型接口（最实用的场景）

学生、老师都要增删改查 → 不用写两份接口：

```java
public interface Data<T> {
    void add(T t);
    void delete(T t);
    void update(T t);
    T find(int id);
}

public class StudentData implements Data<Student> { ... }  // T → Student
public class TeacherData implements Data<Teacher> { ... }  // T → Teacher
```

**实现类在 `implements` 时把类型"定死"**（`Data<Student>`），接口里所有 T 就全部替换成 Student——这就是泛型接口的核心用法。

### 2.3 泛型方法

```java
public static <T> void printArray(T[] names) { }
public static <T> T getMax(T[] names) { return null; }
```

**区分点**：方法声明处的 `<T>` 才是"自己定义泛型"；如果方法返回值用到的 T 来自**类的声明**（如 `T get()`），那不叫泛型方法。

一个 `printArray` 能打印任意类型的数组，不用为每种类型各写一份——这就是泛型方法存在的意义。

## 三、泛型通配符 `?`

### 3.1 为什么需要 `?`

```java
ArrayList<Xiaomi> xiaomis = ...;
ArrayList<Weilai> weilais = ...;

// ❌ 编译报错：泛型之间没有继承关系！
public static void go(ArrayList<Car> cars) { }

go(xiaomis);   // 虽然 Xiaomi 是 Car 子类，但 ArrayList<Xiaomi> 不是 ArrayList<Car>
```

> **虽然 Xiaomi 是 Car 的子类，但是 `ArrayList<Xiaomi>`、`ArrayList<Weilai>` 和 `ArrayList<Car>` 之间没有任何关系！泛型之间不存在继承。**

### 3.2 `?` + 上下限

通配符的本质：**给"使用泛型"时一个范围**。

| 写法 | 名称 | 含义 |
| ---- | ---- | ---- |
| `<?>` | 无界通配符 | 什么都能收 |
| `<? extends Car>` | 泛型上限 | 必须是 Car 或者其子类 |
| `<? super Car>` | 泛型下限 | 必须是 Car 或者其父类 |

```java
// 上限：只能接收 Car 及其子类的集合（小米车队、蔚来车队都可以，狗不行）
public static void go(ArrayList<? extends Car> cars) { }
```

**注意区分**：`?` 是在**使用**泛型时用的；`E`、`T`、`K`、`V` 是在**定义**泛型时用的。

## 四、泛型擦除（重点）

### 4.1 什么是擦除

**泛型工作在编译阶段，等编译后泛型就没用了，所以泛型在编译后都会被擦除，所有类型会恢复成 Object 类型。**

验证代码：

```java
ArrayList<String> list1 = new ArrayList<>();
ArrayList<Integer> list2 = new ArrayList<>();
System.out.println(list1.getClass() == list2.getClass());  // true
```

`true` 说明在 JVM 眼里 `ArrayList<String>` 和 `ArrayList<Integer>` 根本就是同一个 `ArrayList`——泛型信息只存在于源码和编译阶段，编译完就全部擦掉。

这也是 Java 的泛型常被称为「**伪泛型**」的原因。

### 4.2 擦除干了三件事

1. 泛型类内部声明中的 T → 替换为上界（无界就是 Object）
2. 调用处的类型实参被擦掉
3. 取值时自动补强转

## 五、泛型的 5 个限制（根因都是擦除）

### ① 不能 `new T()`

```java
T t = new T();   // 编译报错
```

**疑问**：擦除后 T 不是变成 Object 吗？那 `new Object()` 不就行了？

不行。**擦除替换的只是「T 作为类型被引用」的位置**——字段声明、方法参数、返回值。这些地方换成 Object 后语义不变：

```java
// 源码                          // 擦除后
class Box<T> {                   class Box {
    private T content;               private Object content;  // T → Object
    public T get() {                 public Object get() {
        return content;                  return content;
    }                              }
}                              }
```

而 `new T()` 不是"类型引用"，是**创建对象的动作**——它需要的是"T 此刻到底是哪个具体类"，这个信息恰恰是擦除删掉的。

**补救**：传 `Class<T>` 进来，运行时靠它才知道 new 谁：

```java
T create(Class<T> clazz) throws Exception {
    return clazz.newInstance();
}
```

### ② `instanceof` 不能判断具体泛型

```java
List<String> list = new ArrayList<>();
// list instanceof ArrayList<String>   // 编译报错
list instanceof ArrayList<?>           // ✓ 合法
```

**根因**：`instanceof` 是**运行时**检查，擦除后 `ArrayList<String>` 和 `ArrayList<Integer>` 在 JVM 里一模一样——String 信息根本不存在，这个问题运行时答不上来，编译器干脆提前禁止。

> 类比：两个贴了不同标签的盒子，出厂时标签全被撕了（擦除）。你问"这是不是贴 String 标签的那个？"保安看不到标签，答不了；但问"这是不是个盒子"（`ArrayList<?>`），保安能答。

### ③ 不能创建泛型数组

```java
List<String>[] arr = new ArrayList<String>[10];   // 报错！
List<?>[] arr2 = new List<?>[10];                  // ✓ 合法
```

**根因**：数组有两个天性与泛型擦除打架：
1. 数组**协变**（`String[]` 可以当 `Object[]` 用）
2. 数组**运行时记得自己的元素类型**

假设允许，灾难链：

```
String[] strs = new String[3];
Object[] objs = strs;             // 数组协变允许
objs[0] = new Integer(1);          // 运行时检查元素类型 → 抛 ArrayStoreException ✓ 拦截
```

但泛型数组擦除后只记得自己是 `List[]`：

```
List<String>[] arr = new List<String>[10];   // 假设允许
List<Integer> intList = new ArrayList<>();
arr[0] = intList;                              // 运行时擦除后只查"是不是 List" → 通过 ✓
String s = (String) arr[0].get(0);             // ClassCastException，悄悄埋雷
```

所以干脆禁止。**替代方案**：`List<List<String>>`。

### ④ 静态成员不能用类的类型参数

```java
class Box<T> {
    static T value;       // 编译报错
    static <E> E pick(E[] arr) { ... }   // ✓ 静态泛型方法
}
```

**根因**：T 是**对象级**的约定（每个对象独立），static 是**类级**的（一份、全共享）：

| 维度 | 类的 T | static 成员 |
| ---- | ---- | ---- |
| 时间 | `new Box<>()` 时才确定 | 类加载时就存在 |
| 空间 | 每个对象一份 | 全类共享 |

两层都对不上。

> 注意：**静态泛型方法是合法的**。`<E>` 是方法自己声明的类型参数，不依赖任何对象。

### ⑤ 基本类型不能作为类型参数

```java
List<int> list;       // 编译报错
List<Integer> ok;     // 要用包装类
```

**根因**：擦除后类型参数要变成 Object，而 `int` 不是对象。

> 这也是包装类存在的意义之一（自动装箱/拆箱让基本类型和包装类之间可以无缝转换）。

---

## 六、泛型不支持基本类型 → 包装类

```java
ArrayList<Integer> list = new ArrayList<>();
list.add(138);     // 自动装箱：int → Integer

int i = list.get(0);   // 自动拆箱：Integer → int

String s = "98";
int num = Integer.valueOf(s);  // 字符串转基本类型
```

> `parseXXX()` 等价于 `valueOf()`：前者直接返回基本类型，后者返回包装类后自动拆箱。

---

## 七、总结口诀

| 限制 | 一句话根因 |
| ---- | ---- |
| ① `new T()` | 擦除删的是"T 是谁"的信息 |
| ② `instanceof` | 运行时泛型信息已不存在 |
| ③ 泛型数组 | 数组协变 + 数组记元素类型，与擦除冲突 |
| ④ `static T` | T 是对象级，static 是类级 |
| ⑤ 基本类型 | 擦除后要变 Object，int 不是对象 |

**一句话总结**：泛型是编译器帮你做的类型检查 + 自动强转，JVM 从头到尾都没见过泛型。
