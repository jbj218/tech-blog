# Redis 入门：键值型 NoSQL 的本质

> 这篇博客对应我学过的《Redis入门篇/Redis.md》整理。

## 一句话定位

**Redis 是一种基于内存的键值型 NoSQL 数据库。** 它把数据存在内存里而不是磁盘上，所以读写速度极快（10 万 QPS 级别），通常用来做缓存、计数器、消息队列、分布式锁——任何需要"快"的场景。

---

## 一、NoSQL 与关系型数据库的核心差异

### 1.1 结构化 vs 非结构化

| 维度 | 关系型数据库（MySQL） | NoSQL（Redis） |
| ---- | ---- | ---- |
| 数据格式 | 严格结构化（字段名、类型、约束） | 形式松散、自由 |
| 典型形态 | 表格 | 键值型 / 文档型 / 图格式 |
| 约束 | 主键、唯一、外键、NOT NULL | 没有 |

```
键值型：{ key1: value1, key2: value2 }
文档型：{ id: 1, name: "张三", orders: [...] }
图格式：节点 + 边的网状关系
```

### 1.2 关联 vs 非关联

**关系型数据库**：表与表之间有外键关联，靠 SQL JOIN 查询。

**NoSQL**：不存在关联关系，要维护关系只能：
- 靠业务代码
- 靠数据本身的耦合（嵌套）
- 一次性把"父+子"数据查出来塞进 JSON

### 1.3 ACID vs BASE

| 维度 | 关系型 | NoSQL |
| ---- | ---- | ---- |
| 事务 | ACID（强一致性） | BASE（最终一致） |
| 扩展方式 | 纵向（加 CPU、内存） | 横向（加机器） |
| 适用 | 强一致业务（金融、订单） | 海量数据、高并发（缓存、计数） |

## 二、Redis 的核心特征

### 2.1 三大特点

| 特点 | 含义 |
| ---- | ---- |
| **键值型** | 数据以 `key:value` 形式存储 |
| **基于内存** | 主要数据存在内存中，读写极快 |
| **可选持久化** | 可以把内存数据异步落盘（RDB / AOF） |

### 2.2 value 的 5 种常见数据结构

这是 Redis 与"简单键值缓存"（如 Memcached）的核心区别——value 不只是字符串，还能是复杂结构：

| 数据结构 | 典型用途 |
| ---- | ---- |
| **String** | 缓存 JSON、计数器、分布式锁、Session |
| **Hash** | 存对象（用户信息、商品详情） |
| **List** | 消息队列、最新列表 |
| **Set** | 共同好友、标签、去重 |
| **SortedSet（ZSet）** | 排行榜、带权重的去重 |

### 2.3 Redis 解决了什么问题

**典型应用场景**：
- 缓存（挡掉 99% 的 MySQL 请求）
- 计数器（点赞数、阅读量）
- 分布式锁（`SETNX`）
- 消息队列（Stream / Pub-Sub）
- 排行榜（SortedSet）
- 共同好友（Set 求交集）
- UV 统计（HyperLogLog）

## 三、为什么 MySQL 撑不住高并发

```
单台 4 核 8G Tomcat ≈ 1000 并发
单台 MySQL（16-32 核 + SSD）≈ 4000-7000 并发

→ 上万并发的瞬间，MySQL CPU/硬盘直接打满
```

**解决方案架构**：

```
浏览器/手机
    ↓
Nginx（负载均衡 + 静态资源 + Lua 直访 Redis）
    ↓
Tomcat 集群（负载均衡打散流量）
    ↓
Redis 集群（缓存 + 计数器 + 分布式锁 + MQ）
    ↓
MySQL 集群（最终落库）
```

**Redis 在整个架构中的角色**：在 Tomcat 和 MySQL 之间挡一道，把 99% 的热点请求拦住，避免 MySQL 被流量打爆。

## 四、Redis 的 Java 客户端

| 客户端 | 特点 | 推荐度 |
| ---- | ---- | ---- |
| **Jedis** | 早期主流，同步阻塞模型，线程不安全 | ⭐⭐⭐ |
| **Lettuce** | Spring Boot 默认，Netty 异步、线程安全 | ⭐⭐⭐⭐ |
| **Redisson** | 分布式锁、集合高级操作、企业级特性最全 | ⭐⭐⭐⭐⭐ |
| **Spring Data Redis** | 对 Jedis / Lettuce 的统一封装 | 日常开发主力 |

实际项目里最常见的搭配是 **Spring Data Redis + Lettuce**（Spring Boot 默认），需要分布式锁高级特性时引入 **Redisson**。

## 五、键值型数据库的存储思想

### 5.1 key 的设计原则

**Redis 的 key 没有强制结构，但好的 key 设计让你 6 个月后还能看懂**：

```
业务模块:对象类型:ID:字段
```

例如：
```
user:profile:1001        → 用户 1001 的资料（JSON 字符串）
shop:detail:2001          → 店铺 2001 的详情（Hash）
order:queue               → 订单队列（List）
seckill:voucher:stock     → 秒杀券的库存（String，incr/decr）
lock:order:pay            → 订单支付锁（String，SETNX）
```

### 5.2 value 的选型思路

| 需求 | 推荐结构 |
| ---- | ---- |
| 简单计数、单个字段 | String |
| 对象（多字段） | Hash（可以单独改字段） |
| 队列、最新 N 条 | List |
| 去重集合、共同好友 | Set |
| 排行榜、按分数排序 | SortedSet |
| 海量去重统计（容忍误差） | HyperLogLog |
| 用户签到 | BitMap |

## 六、总结口诀

| 概念 | 一句话 |
| ---- | ---- |
| **Redis 是什么** | 基于内存的键值型 NoSQL，支持 5 种数据结构 |
| **能干什么** | 缓存、计数、锁、队列、排行榜 |
| **为什么快** | 数据在内存里 + 单线程避免锁竞争 + IO 多路复用 |
| **怎么选 value** | 计数用 String、对象用 Hash、队列用 List、去重用 Set、排序用 ZSet |

**一句话**：Redis 是高并发架构里最常用的"缓冲层"，理解"为什么 NoSQL"比"会用 5 种命令"更重要。
